# Правила разработки WB Profit Firewall

## UI и дизайн

- Проект использует чистые HTML, CSS и JavaScript без React/Tailwind и без внешних UI-фреймворков.
- Единый визуальный стиль: строгий финансовый SaaS-интерфейс, тёмно-синяя навигация, синие акценты, светлый фон, карточки с тонкой рамкой и умеренной тенью.
- Все общие цвета, размеры, радиусы и отступы задаются CSS-переменными в `public/styles.css`.
- Новые экраны и компоненты сначала собираются из существующих классов (`.card`, `.panel`, `.pill`, `.btn`, `.table-wrap`), а новые классы добавляются только при необходимости.
- Не подключать React, Tailwind, shadcn/ui, MUI или CDN-библиотеки без отдельного решения: приложение должно запускаться локально командой `npm.cmd start` без сборщика.
- Интерфейс обязан оставаться удобным на экранах от 360 px; проверять мобильную ширину перед завершением задачи.

## Финансовые расчёты

- Бизнес-логику держать в `src/analyze.js`, API-интеграции — в `src/wb-api.js`.
- Не подменять неизвестную себестоимость нулём и не показывать неподтверждённую прибыль.
- Для вариантов одной карточки точный баркод имеет приоритет над `nmID`.
- Любое изменение формулы сопровождается тестом в `test/` и пояснением в README.

## Проверка перед коммитом

```powershell
npm.cmd test
node --check public/app.js
```

Не добавлять в Git токены WB, `.data/`, отчёты, CSV/XLSX-файлы и персональные данные.
